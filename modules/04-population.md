# 模块：人口（岗位 · 分工 · 关系 · 疾病 · 异能）

> 所属层：玩法层  
> 依赖：列车（床位/岗位槽）、资源（粮水药、药剂）、时间  
> 被依赖：战斗战力、事件条件、种植/工坊产出  
 
> **人口无硬上限**：加挂休息车厢 → 床位↑ → 可持续收留；生产岗与战斗岗随车厢与编成扩展。  
> 定居点派驻已延后（见 archive/settlement-deferred.md）。

---

## 1. 设计意图

全员完整个体——姓名、背景、专长、缺陷、关系、忠诚、mood、执念 `desire`、遗言。不设派系、不设「核心/路人」（红线 #3/#4）。

```
车厢可无限加挂
  → 休息车↑ = 床位↑ = 人口可无限增长（软压：粮水、疫情、燃油、操作负担）
  → 功能车↑ = 岗位槽↑ = 可养更多生产人员
  → 多余人力 → 战斗小组 / 点名搜索 / 杂工搬运
```

「车上人口 20」只是**软目标里程碑**，不是人数封顶。

**岗位 = 车厢槽位绑定的当日工种**（无 RPG 职业树 / **无岗位熟练度**）。异能有**单局内**熟练度，仅用于解锁 Lv2（§8.1），不碰红线 #11。  
 
**专长 = 软加成标签**（匹配岗位或任务时生效；不锁岗）。  
**车外任务三分工（权威 §5）**：搜索＝任意可派人点名；战斗＝战斗小组；搬运＝杂工。伤员不可派；任何进行中任务可打断召回。

## 2. 成员字段（必须存档）

`id, name, age, background, specialties, flaw, hp, loyalty, mood, job, jobTrack, carId, relations, desire, deathQuote, injuries, disease, antibodies, traits, combatRoster, loadout, taskState, abilities[{id,lv,proficiency,cooldownUntilDay}], hunger, thirst`

- `hunger` / `thirst`：**0–100**，S1b 客户端逐人饥渴（Banished 式日内 tick + 日结 `reconcile` 锁日总耗，见 [02 §8 步骤 2](02-resources.md)、[01 §2.3](01-time-season.md)）；从全车粮水池取食（非个人库存）  
- `job`：闭合枚举，见 §4.2  
- `jobTrack`：由 `job` 推导：`production | combat | support | labor | none`  
- `specialties[]`：0–2 个专长标签（§4.5）；旧存档单值 `skill` 迁移为单元素数组  
- `combatRoster`：是否编入**战斗小组**名册；权威见 §4.6  
- `loadout`：默认战斗装备  
- `taskState`：`idle | searching | hauling | in_combat | returning | unavailable`（无 `assigned_search`；点名即进入 `searching`）  
- 编队/占位：全局 `formations[]`（[05](05-combat.md)）

缺叙事字段时按原型表以 id 种子回填，禁止空串。

## 3. 规模：床位门控，不设人数天花板

- 床位权威：[列车 §3.2](03-train.md)（预满 `Σ(living.size×carriages.livingBedsPerSize) + living_tech×carriages.techBedsPerLivingLevel`；默认两键均为 2）  
- **无** `maxPopulation`；门槛是床位与粮水  
- 开局：休息 size2 → 4 床 = 4 人住满  
- **满床不封锁收留**（有意软压）：无空床仍可收留进过道（`carId=null`），权重 ×0.35，mood −3/日；教程站送休息车正是为缓解此压

## 4. 岗位与专长（权威）

岗位槽随功能车扩展。同一人同时占 **1** 个岗位槽；同时最多接 **1** 条车外任务。  
**禁止**把「精炼」写成岗位——精炼是工坊日模式（`crafter` 在岗时选「造零件 XOR 精炼」，见 [02 §5.1](02-resources.md)）。

### 4.1 轨道

| 轨道 | 含岗位 | 作用 |
|---|---|---|
| **production** | grower / crafter / purifier | 车内产出 |
| **combat** | guard | 默认进战斗名册 |
| **support** | pharmacist / radar_op / engineer | 医疗+药剂 / 视野 / 动力看护 |
| **labor** | labor | **只**跑搬运（点位→车厢入库） |
| **none** | none | 闲置；mood −2/日；可被点名搜索或改派 |

### 4.2 闭合岗位表

| job | 名 | track | 槽来源 | 无人后果 |
|---|---|---|---|---|
| `grower` | 种植 | production | greenhouse ×1 | 该车 F05 = 0 |
| `crafter` | 工坊 | production | workshop ×2 | 该工位日产出 0（含造零件/精炼） |
| `purifier` | 净水 | production | water ×1 | 该车 F32 = 0 |
| `pharmacist` | 药剂师 | support | medical ×1 | 不可治疗 / 不可制 `medicine` / 不可配药剂 |
| `radar_op` | 雷达员 | support | radar ×1 | 该节雷达**不计入**视野 |
| `engineer` | 动力看护 | support | 每节动力车 ×1 | 见 §4.7 |
| `guard` | 守卫 | combat | 无车厢槽；进 `combatRoster` | 名册无人则无法开编队战 |
| `labor` | 杂工 | labor | 无车厢槽 | 临时堆搬不进车；**岗位职责仅搬运**，但仍可被点名**搜索**（搜索不是岗位，见 §5.1） |
| `none` | 无岗 | none | — | mood −2/日 |

**无 `medic` 岗**：治疗、试剂→药品、晶核→药剂均由 `pharmacist` 承担（§4.4）。

### 4.3 槽位与调度

| 规则 | 口径 |
|---|---|
| 自动填槽 | 按下方**优先级序**填空槽；可锁定；已锁定不挤占 |
| 调岗时机 | **暂停**可改 `job` 与名册 |
| **生产 + 搜索** | `grower`/`purifier` 兼搜 → **仍计在岗**，F05/F32 照常。`crafter` 兼搜 → 当日**不计入**造零件/精炼工位（与修车占工位同构，[03 §4](03-train.md)）；种植/净水不受影响 |
| 支援暂离 | 支援岗出车**搜索** → 当日该支援槽视为空（搬运仅 `labor`，支援不能接搬运单，见 §5.1） |
| 无搜刮员编制 | 搜索不占岗位槽（§5.1） |

**自动填槽优先级（高→低）**；同优先级：有匹配专长者优先，再按 `mood` 高者，再按 `id` 稳定序。人少时先保证序前槽。

1. `grower`（有种植车空槽）  
2. `purifier`（有净水车空槽）  
3. `engineer`（有动力车失护或空槽）  
4. `crafter`（有工坊空位）  
5. `pharmacist`（有医疗车空槽）  
6. `radar_op`  
7. 不自动派 `guard` / `labor` / `none`（需玩家或事件）

### 4.3.1 开局四人编制（权威）

开局编组仅动力 + 休息 + 货舱（无种植/净水/医疗/工坊/雷达槽）。四人固定 **4 人**；`job` 初始均为 `none`，由玩家在搜索面板指派（`SET_MEMBER_JOB`）。专长与 `combatRoster` 仍按 `archetypes.json` 权威：

| 槽序 | `job`（开局） | 专长 / 战斗 | 说明 |
|---|---|---|---|
| 1 | `none` | — | 玩家可派 `engineer` 等填动力看护 |
| 2 | `none` | `combat_drill`，`combatRoster=true` | 保证默认编队可上场 ≥1（[05 §2](05-combat.md)） |
| 3 | `none` | `haul` | 早期搬运/搜索教学 |
| 4 | `none` | `scavenge` | 搜刮倾向；搜索不占岗（§5.1） |

开局**不**在 `seed` 时跑自动填槽；日末 `assign_daily_jobs` 仍可从 `none`/`labor` 池填功能车空槽。禁止开局名册为空。收留新人：按 `archetypes.json` 倾向赋 `job`，再跑自动填槽；无倾向则 `none`。

### 4.4 医疗槽：药剂师（合一）

医疗车 **1 岗** = `pharmacist`。在岗且条件满足时可做：

| 动作 | 条件 | 规则 |
|---|---|---|
| 正规治疗 / 隔离协助 | 有医疗台 | [§7](#7-疾病)；疗程见专长 |
| 试剂 → 药品 | 停靠 | [02 §5.2](02-resources.md) |
| 配制药剂 | 停靠 | [02 §5.4](02-resources.md) |

- 无人 → 不可治疗、不可制药品、不可配药剂  
- 同日可穿插治疗与配制（队列串行，不互斥岗位）  
- 出车搜索/搬运期间：本槽视为空（支援须在车）  

### 4.5 专长（软加成；不锁岗）

`specialties[]`：0–2 个。无专长也可上对应岗，只是无加成。  
开局/收留按 `archetypes.json` 抽取。事件可授予（仍受上限 2；已满则不覆盖，除非玩家确认替换）。  
**禁止**专长直接产资源或绕过岗位槽。

| specialty | 匹配条件 | 效果 |
|---|---|---|
| `scavenge` | 被派搜索 | 该人搜索**效率** ×(1/0.85)（时长约 ×0.85，见 §5.3）；重复搜索受伤权重 ×0.8（[02 §7](02-resources.md)） |
| `repair` | 参与车体维修动作 | 维修时长 ×0.85（[03 §6.3](03-train.md)） |
| `medicine` | `job=pharmacist` 且在治该病人 | 普通疗程 **2 日**（默认 3 日；仍 1 药/日） |
| `pharmacy` | `job=pharmacist` 配制中 | 配制时长 ×0.75 |
| `farming` | `job=grower` 在岗 | 该岗负责车的 F05 ×1.10 |
| `haul` | `job=labor` 接搬运单 | 该单时长 ×0.85 |
| `combat_drill` | 本场上场 | **双效果**（[05 §4/§7](05-combat.md) 须同时实现）：① 个体战力 ×1.05；② 每回合 0.12 爆发检定，成功则本回合输出 ×1.6 |

### 4.6 战斗名册与 `guard`

权威：**仅** `combatRoster=true` 可编入编队上场。

| 情况 | 规则 |
|---|---|
| 设 `job=guard` | 自动 `combatRoster=true`、`jobTrack=combat` |
| 改离 `guard` | 若未勾「保留名册」→ `combatRoster=false`；已在编队者须先移出 |
| 紧急征召 | 生产/杂工/支援勾进名册 → **只**改 `combatRoster`，**不**改 `job`；须先打断召回车外任务，到车后才能上场；战后可移出名册，原岗不变 |
| 默认 | 非 `guard` 的 `combatRoster=false` |

### 4.7 动力看护（可测）

每节 `isLocomotive` 动力车需要 1 名 `engineer` 在岗。

- **有看护**：正常。  
- **无看护**：若该节**当前无失护状态**，每日一次故障检定，基础概率 **10%**（`power.unattendedFaultChance=0.10`）；触发 → 失护，速度上限 ×0.85。  
- **解除**：① [03 §6.3](03-train.md) **失护检修**成功；或 ② 满 **1 游戏日**自动解除（取先到者）。车体维修一不解除。  
- **自动解除后**：即使仍无看护，当日不再二次判定；**次日** `onDayStart` 若仍无看护，重新进入「可判定」池。有看护的节：不判定、不新触发；已有失护仍须检修或等自动解除。  
- 多节分别判定。速度结算见 [03 §7](03-train.md)。

## 5. 车外任务（搜索 · 战斗 · 搬运）— 权威

### 5.1 指派总表

| 任务 | 谁干 | 如何指派 | 产出/作用 |
|---|---|---|---|
| **搜索** | **任意可派人**（1–4 人/点）；**无搜刮员岗位** | 点位面板点名；列表将 `scavenge` 专长置顶 | 扣点位 `remainingYield`→临时堆 |
| **战斗** | **战斗小组**（现行编队上场≤8） | 只用 `combatRoster`+编队；非名册不上场 | L1/L2/L3 结算 |
| **搬运** | **杂工**（`job=labor`） | 搜索出货后自动生成搬运单，或手动加派 | 临时堆→列车库存 |

可派池：非 `unavailable`，且 `taskState` 不在互斥任务中（searching/hauling/in_combat/returning）。  
禁止：用战斗小组去搬运刷效率；禁止用杂工顶战斗名册（除非紧急征召进名册，§4.6）。

### 5.2 战斗小组

- 开战只抽**当前编队**（[05](05-combat.md)），不从搜刮/杂工/生产里自动抓人  
- 紧急征召：见 §4.6（不毁原 `job`）  
- 搜索进行中的人：**不可**同时进本场战斗；须召回完成或弃物回车  

### 5.3 搜索流程

```
停车（速度=0）→ 选点位 → 指定 1–4 名可派人员（可含生产岗）
  → taskState=searching
  → 生产岗：仍计在岗产出（§4.3）；支援岗：该槽当日空
  → 进度条（时长公式见下）
  → 完成：物资进「点位临时堆」→ 自动生成搬运单给杂工
  → 无杂工可用：临时堆**一直留在该点**，UI 提示「待搬运」
```

**搜索时长（权威）**：

```
每人效率 = 有 scavenge ? (1/0.85) : 1.0    # 搜刮专长加快，约 1.176
队伍效率 = Σ 每人效率
人数修正 = 0.85^(人数−1)                 # 1→1.0；2→0.85；3→0.7225…
时长游戏小时 = max(0.5, 1.0 × 人数修正 × (人数 / 队伍效率))
```

校验：1 人无专长 → 1.0；1 人有 `scavenge` → ≈0.85；2 人皆无 → 0.85。  

**S1b 客户端工时与日钟（与上式并行，薄实现）**：搜索/搬运进度由 `balance.search.hoursProgressPerDay` / `balance.haul.hoursProgressPerDay` 按 **`day_delta` 积分**；仅 `driveIntent==outdoorWorkRequiresIntent`（默认 `stop`）推进；日末补 `outdoorEligible−outdoorTick`（[01 §2.3](01-time-season.md)）。完整游戏小时公式仍为权威，sim/对表可先走日结补课路径。
**禁止**把「贡献小时 0.85」直接做分母分子颠倒（会变成专长反而变慢）。  
下限 0.5 作用在**总时长**。重复搜索受伤见 [02 §7](02-resources.md)。收留见 [06 §2.2](06-region-events.md)。

### 5.4 临时堆（不自动蒸发）

- 临时堆挂在**点位**上，不随列车移动  
- **禁止**超时/跨区段自然衰减或发车清零  
- 唯一减少方式：  
  1. 杂工搬运入库  
  2. **被其它单位夺走**（掠夺者/尸潮扫荡/武装搜刮等：事件选项或战斗战败/弃物撤退）  
- 夺走路径（闭环）：  

| 触发 | 默认夺走比例 | 权威 |
|---|---|---|
| 掠夺/扫荡事件选项失败 | 配置；缺省 50–100% | 06 事件 |
| L2/L3 战败 | 100%（事件可减半） | 05 §7 |
| 平局撤退 / 弃物撤退 | 100% | 05 §6.3 |
| 绕行失败 | 50% | 05 §6.3 |
| 鸣笛失败 | 0%（堆保留） | 05 §6.3 |
| 徒步撤离（成/败） | 100% 放弃 | 05 §6.3 |
| 非战斗成功（谈/绕/鸣） | 0% | 05 §6.3 |

可派战斗小组清场保护（降低事件夺堆权重，不免疫战败夺堆）。
- 满仓溢出：仍留堆，等有空位再搬  
- **存档**：`world.lootPiles[]`（pointId + 物资）；列车驶离后仍保留，可返程；不因「离开区段」删除  

### 5.5 搬运（杂工）

- 仅 `job=labor` 且可派者接单；每单 1 名杂工（大宗可拆多单）  
- 基线时长 0.4 游戏小时/单；有 `haul` 专长 → ×0.85  
- 入库受 [02](02-resources.md) 上限；搬不完继续留堆，待有空位或下次指派

### 5.6 伤员不可指派

下列任一成立 → `unavailable`，**禁止**派搜索/战斗/搬运（含紧急征召）：

| 条件 | 说明 |
|---|---|
| `injuries` 含行动受限标签 | 重伤、腿伤等（战斗/事故写入） |
| 疾病状态 = 发病 | 首发：发病不可派 |
| `hp ≤ 30%` | 虚弱 |
| `taskState=returning` 且尚未到车 | 召回途中不可改派其它任务 |

轻伤（仅 mood/叙事、无行动受限）：可派。治疗完成后解除。

### 5.7 打断与召回

| 操作 | 规则 |
|---|---|
| **手动召回** | 对 searching/hauling 下令 → `returning`；耗时 = `max(0.1, 剩余任务游戏小时 × 0.5)`（剩余 = 未完成进度 × 原定总时长）；**已搜出进临时堆的物资仍留在点上** |
| **强制召回** | 速度 **> 8 km/h**：车外人员强制 returning；**进行中搜索进度作废**（未结算进堆的部分不生成）；**已存在的临时堆不清零**，仍留在点上 |
| **战斗插入** | 停车遭袭：战斗小组应战；车外人员自动召回；临时堆仍留点上，本场若战败/选「弃物撤退」可由敌方按 §5.4 夺走 |
| **搬运打断** | 杂工召回：该单物资退回该点临时堆（不是销毁） |

召回到车 → `taskState=idle`；支援槽恢复占用（生产岗搜索期间本未空岗）。

## 6. 关系（唯一权威）

关系值 −100~+100，有向存储。

| 场景 | 变化 |
|---|---|
| 共同搜索成功 | 双方 +3 |
| 战斗中被救 | 被救方对救援方 +15 |
| 资源偏袒 | 另一人对被偏袒者 −8 |
| 亲友死亡（关系>50） | 哀痛 3 日（战力×0.9）；同场目击击杀则复仇×1.3 替代哀痛 |
| 同车厢过冬 | 双方 +10 |
| loyalty < 20 | 跳车事件，一次挽回机会 |

**敌对（≤ −40，同 carId）**：疾病传播 ×1.5；不计过冬 +10；一方受伤另一方 mood −3。

**关系 → 战力（权威映射，[05 §4/§7](05-combat.md) 读取）**：

```
上场人数 ≥2：两两有向关系均值 R ∈ [-100,+100]
上场人数 =1（或无人则本场不应算 P）：R := 0
relationMult = clamp(1 + R/500, 0.80, 1.20)   # 默认 ±20%；单人必为 1.0
若本场 rally 成功：clamp 改为 Lv1 → [0.75,1.25]；Lv2 → [0.72,1.28]
```

乘在 `P` 外层（先算守卫个体与 A，再 × `relationMult`）。哀痛 ×0.9 / 复仇 ×1.3 在**个体**层（§下、05 §4）；复仇覆盖哀痛，不同时乘。

`desire`：事件条件、遗言变体。不直接改战力。

## 7. 疾病

触发：疫情事件、尸群抓伤、低温、或日结时 `foodZeroStreak`/`waterZeroStreak` **刚升到 ≥3 的那一日**（与 [02 §8/§9](02-resources.md) 同一计数）。  
**缺粮疾病检定**：仅在 streak **首次跨入 ≥3** 的日结点，对每名**当前无疾病**成员做一次进入潜伏检定；streak 维持 ≥3 的后续日**不**每日重复触发（只叠 F39）。治愈后若 streak 仍 ≥3，则**次日**可再检定一次。  
与 F39（缺粮水 hp −20/日）**可同日并存**——疾病走病程，F39 走资源归零；不互相替代、不互相取消。  
病程：潜伏 → **发病（不可派车外任务）**（hp −4/日）→ 发病日每日 10% 死亡；**第 7 日仍存活则自动康复**（未治疗亦然）。  
传播：同 `carId` 15%/日（医疗车在场 5%）；**过道**（`carId=null`）**20%/日**（高于有床，落实「超员更易染」）。  
过道额外：若车上人口 > 床位且当日尚无疫情事件，每日 5% 对一名过道成员检定进入潜伏（软压播种；有床者不检）。  
治疗：普通疗程默认 **3 日**、1 药/日；在岗 `pharmacist` 且有 `medicine` 专长 → **2 日**、仍 1 药/日（与 §4.5 同一口径；禁止读成「消耗×2」）。强化 2 药当日痊愈。可隔离。  
须医疗车厢有 `pharmacist` 在岗（出车搜索期间本槽空，见 §4.3）。

## 8. 异能（药剂驱动）

红线（架构 #9）：**不产资源**；有**药剂**代价；有冷却与失败率；**不保底成功**；失败仍扣消耗。  
**晶核是原料，不是发动货币**——须经药剂师配成药剂后再用（[02 §5.4](02-resources.md)）。

每局觉醒者上限 **3**；一人至多持有 **1** 个异能。战前从上场成员中点选用（[05](05-combat.md)）。

### 8.1 觉醒 · 熟练度 · 升级

| 步骤 | 条件 | 消耗 / 触发 | 结果 |
|---|---|---|---|
| **觉醒** | 第 2 年起；觉醒者 < 3；目标无异能；停靠 | 饮用 `potion.awaken` ×1 | 写入异能 id；`proficiency=0`；`maxLv=2` |
| **熟练度** | 每次异能判定（埋点 `ability_proc`） | 成功 +20；失败 +5（配置 `ability.proficiencyPer*`） | `proficiency` clamp 到 0–60；**单局内**，不跨局 |
| **升级** | 已觉醒；当前 Lv1；`proficiency ≥ 60`（`ability.proficiencyThreshold`） | 饮用 `potion.upgrade` ×1 | Lv→2；效果用 §8.3「升级」列；`proficiency` 清零 |

- 熟练度决定「**何时能升**」；升级药剂决定「**有无资格执行升**」——缺一不可  
- **禁止**仅嗑药升到 Lv2（`proficiency < 60` 时升级药剂不可用/提示未熟练）  
- **禁止**事件直接发异能而不扣觉醒药剂（可赠瓶再由玩家喝）  
- **禁止** raw `crystal` 点觉醒/升级  
- 年 1：不可配觉醒药剂；岗位/战斗仍无 RPG 熟练度

### 8.2 分系

| 系 | 职责 | 进结算位置 |
|---|---|---|
| **战斗系** | 抬输出、破甲、斩杀压力 | 多进战力式 `A` 或本场 `outP` 修正 |
| **防护系** | 挡伤、减伤 | 进战力式 `A` 或压本方 `outE` 分摊 |
| **辅助系** | 侦察、治疗、士气、控场、急援 | 进战力式 `A` / 非伤害效果 / 流程打断 |

### 8.4 使用规则

- 每场战斗每名觉醒者至多发动 **1** 次异能（先于回合结算声明）  
- 声明时扣库存；催化药剂不足 → 不可声明  
- 同场可多名觉醒者各放 1 个；战力式 `A` 为各成功效果按**当前异能等级 Lv**求和（≠ 战斗层级 L1–L3）  
- 失败：播报失败，冷却照进，药剂不退  
- **冷却边界**：发动日（成功或失败）写 `cooldownUntilDay = dayTotal + cooldownDays`；当 `dayTotal ≥ cooldownUntilDay` 可再声明（**当日可恢复**，非次日清晨）。缺省 / 迁移缺字段 → `0`（立即可用）  
- **禁止**用异能直接加食物/燃料/零件/晶核或搜刮产量  
- **禁止**战斗结算扣 raw `crystal`

## 9. 集体士气

### 9.1 成员心情日结（权威；先于集体士气）

在 [02 §8](02-resources.md) 步骤 **7b** 执行，对每名在册成员（含过道成员）：

```
Δmood = −1.5                                   # 基线：长期生存磨损
      + (carId != null ? +1.0 : 0)             # 有床；过道另按 03 §3.2 −3/日
      + (当日 food 与 water 均未 WentZero ? +0.8 : 0)
      + (同车存在 relation > 50 的同伴 ? +0.4 : 0)
      + 0.2 × 生活科技等级                     # 03 §7
mood = clamp(mood + Δmood, 0, 100)
```

- 条件良好时净值 **+0.7 + 0.2×等级**/日：心情缓慢回升，**不设**隐性死亡钟。
- 任一条件缺失即转负；过道 / 无岗 / 敌对仍按各自惩罚叠加，此处不重复扣。
- 事件、`rally`、共同搜索成功、同车过冬等一次性加减照旧。
- 生活科技**不增加**心情衰减（原「mood 日衰减 −0.5/级」废止，按 03 §7 改为 +0.2/级恢复）。

### 9.2 moraleOffset 两侧规则

**负侧下限**：`moraleOffset = max(moraleOffset, −60)`；连续缺粮水可压低集体士气，但偏移本身不跌破 −60（有意失败路径仍靠 F39 / streak，见 [02 §9](02-resources.md)）。  
**负侧回正**：若当日**无**下列任一惩罚源，则 `moraleOffset = min(0, moraleOffset + 2)`（向 0 回，不越过正）：  
`foodWentZero` / `waterWentZero` / 战败或平局撤退 / 亲友死亡哀痛触发日。  
**正侧衰减**：若 `moraleOffset > 0`，每日 `moraleOffset = max(0, moraleOffset − 1)`；不受生活科技影响，也不因惩罚源停止。  
惩罚源当日：按 −13（粮）/ −16（水）/ 战斗与哀痛事件表直接扣，**不再**叠加回正。正负两侧互斥，同一日只走一侧。

### 9.3 集体士气与失败计数

步骤 7b **锁死顺序**：① §9.1 改每位 mood → ② §9.2 结算 moraleOffset → ③ 算集体士气 → ④ streak。

```
集体士气 = clamp(成员 mood 均值 + moraleOffset, 0, 100)
若 集体士气 ≤ 0：moraleZeroStreak++
否则：moraleZeroStreak = 0
moraleZeroStreak ≥ 3 → 失败（[07](07-endings-meta.md) 优先 4）
```

存档字段：`moraleZeroStreak`（[09](09-data-platform.md)）。

## 10. 闭环自检

1. 无 `maxPopulation`。  
2. 搜索＝点名可派人（无搜刮员岗）；战斗＝战斗小组；搬运＝杂工。  
3. 临时堆不自动丢失，只被搬走或被敌方夺走。  
4. 伤员/发病/hp≤30% 不可派；召回与 >8 km/h 强制召回可测。  
5. 编队上场 ≤8；名册可更长；`guard` ↔ `combatRoster`；紧急征召不毁原 `job`。  
6. F05 **不**随车上人口缩放（[02 §3](02-resources.md) 固定单车产出）；靠多种植岗/多车喂饱。  
7. 异能觉醒/升级/发动只走药剂；晶核只进药剂师配方。  
8. 医疗槽唯一 `pharmacist`（治疗+制药品+配药剂）。  
9. grower/purifier 兼搜仍在岗；crafter 兼搜当日不计工坊工位；支援岗出车则槽空。  
10. 每个 function 映射到 §4.2 槽规则；精炼不是 job。  
11. 无专长可上岗；专长仅 §4.5 软加成；最多 2 个。  
12. 动力车无 `engineer` → 失护 10% 日故障可测。 
13. 心情有正向基线（§9.1）；生活科技只增恢复、不增衰减；正 `moraleOffset` 每日 −1 归零。
