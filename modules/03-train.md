# 模块：列车（车厢 · 设备 · 发现 · 工坊 · 驾驶 · 科技）

> 所属层：玩法层  
> 依赖：时间、资源、配置加载  
> 被依赖：人口床位、战斗装甲、区域发现池、种植/净水产出

---

## 1. 设计意图

- **发现式加长**：车厢在车站发现，不是零件制造（红线 #13）  
- **壳 + 设备**：车厢是壳（`templateId`），**功能靠车内设备**摆出来，不是只能选成品车  
- **属性可组合**：size / armor / efficiency 等仍可工坊改装  
- **成长即负担**：总容积越大，刹车/切轨越钝；油耗上升  
- **编组可减压**：已挂上的节可在停靠时 **遗弃（脱钩）**，换油耗与节数，不复回发现池（红线 #13 仍禁止「制造新车厢」）  
- **纵向科技**：precision 工具链门槛，不加车厢也能变强

## 2. 车厢属性模型

| 属性 | 范围 | 作用 |
|---|---|---|
| `size` | 1–5 | 总容积；**设备槽位数 = size**；刹车/切轨（超过 8 才惩罚） |
| `function` | null / workshop / medical / greenhouse / water / radar | 由主设备推导（见 §3）；存档可缓存 |
| `armor` | 0–100 | ≥70 计入装甲车 |
| `speedBonus` | −10~+20 | 仅 `isLocomotive` 进入速度上限 |
| `efficiency` | 0–100（高级净水可 150） | 功能产出（种植架/净水等） |
| `equip[]` | 0..size 件 | 车内已装设备 |
| `trait` | 0–1 个 | 发现绑定，工坊不可改 |

**`templateId`（壳，发现写入，工坊不可改）** 与展示名：

| templateId | 展示名 | 默认可装主设备 |
|---|---|---|
| `power` | 动力车厢 | 引擎组件（不可卸导致失去 isLocomotive） |
| `living` | **休息车厢** | 床铺组（提供床位） |
| `cargo` | 货舱 | 货架 |
| `workshop` | 工坊车厢 | 工作台 |
| `medical` | 医疗车厢 | 医疗台 |
| `radar` | 雷达车厢 | 雷达阵 |
| `greenhouse` | **种植车厢**（旧称温室） | 种植架 → `function=greenhouse` → F05 |
| `water` | 净水车厢 | 净水机组 |
| `armor` | 装甲车厢 | 装甲内构（偏防护） |
| `shell` | **空壳车厢** | 无预装主设备；发现池占位，挂上后可按白名单装设备（见 `equipment.json`） |

派生：

- `isLocomotive = (templateId == power)` — **不能**靠拉高 speedBonus 变成动力车  
- 床位：只统计休息车厢内的**床铺类设备**（§3.2）；等价口径仍为 `Σ(living 的 size×2) + 2×生活科技`（开局预装满床铺时）  
- 货舱容量只统计 `cargo`  
- UI/文案统一用「种植车厢」；配置 id 仍为 `greenhouse`（避免存档断裂）

**十种发现模板**（含 `shell`）= 壳 + 预装设备快照；挂上后可在工坊拆装设备（动力资格除外）。

典型油耗增量：多数功能车 +1.0%/日；装甲 +2.0%/日；**首节动力计入基准 3（F04 常数项），每多挂一节动力另 +0.5%/日**（禁止「加动力只降牵引、零增量」导致越长越省油）。大编组仍有油耗软压。

## 3. 车内设备

### 3.1 槽位规则

```
每节设备槽位上限 = size          # size1→1 槽 … size5→5 槽
已用槽位 = Σ 各设备 slotCost     # 常规设备 1；大型 2（净水高级机组、双层种植架）
已用 ≤ 上限；超限不可安装
```

- 设备来源：进站搜刮、事件、工坊制造（`equipment.json`；床铺等耗织物+零件，见 [02 §5](02-resources.md)）  
- **壳限制**：每种 `templateId` 有允许设备白名单。**`templateId` 发现后永不可改**（红线 #13：车厢靠发现，不靠工坊「变种」）。  
- **禁止跨壳**：休息壳不能改装成种植/净水/工坊等；要把车变成种植，必须**发现种植壳**。  
- 同壳内：可换**同壳主设备变体**（功能重分配，白名单见 §4），不兼容设备卸下入库存；`function` = 主设备 function，无主设备则为 null（空壳）；**不能**靠换设备改壳种  

- 同 `function` 重叠惩罚不变：前 2 节不罚，第 3 节起 `0.90^max(0,n−2)`

### 3.2 休息车厢床位（权威）

**定稿密度：预满时 `size × 2`（每槽 1 组床铺 = 2 床）。**

| size | 预满床位 | 体感 |
|---|---|---|
| 1 | 2 | 窄隔间 |
| **2（开局）** | **4** | 标准卧铺节 |
| 3 | 6 | 中段宿舍 |
| 4 | 8 | 大宿舍 |
| 5 | 10 | 极限挤满（单节上限） |

| 项 | 规则 |
|---|---|
| 单节床位 | Σ 该节床铺设备；预满 = `size × 2` |
| `carriages.json` 的 `beds` | **仅 UI/发现预览占位**；运行时床位只认设备安装。开局休息 size2 **预装 2 组床铺** → 运行态 **4 床**（与 `beds:2` 字段无关） |
| 全车床位 | `Σ(休息车厢床位设备) + 2 × 生活科技等级`；科技加床**优先写入休息车**（提高可住 `carId`），禁止科技加床变成无车籍虚空床 |
| 开局 | 1 节休息 size2 → **4 床 = 4 人**，开局即住满（制造「先找休息车/腾床」压力） |
| 设备 | `bunk`：`slotCost=1`，`beds=2`；可拆床腾槽给储物 → 床位下降 |

**为何是 ×2**：开局 4 床对齐 4 人；之后**人口无硬顶**——多挂休息车即可多住人（见 [04](04-population.md)）。×1 早期过虐；×3 开局空床、早期无压力。

里程碑（非上限）：车上约 20 人 ≈ 休息 size 合计 8–10，或 size8 + 生活 Lv2。

**超员**：无空床仍可收留 → `carId=null`（过道）→ mood −3/日、疫病抗性较差；收留权重 ×0.35（[04](04-population.md)/[06](06-region-events.md)）。**加挂休息车是正道，不是人数封顶。**

**列车长度**：节数/容积**无硬上限**；软压 = 油耗、刹车/切轨、视图切换（§8）。岗位槽随功能车增加，供生产编成无限扩。

### 3.3 种植车厢（greenhouse）

- 展示名：**种植车厢**；产出公式仍是 [资源 F05](02-resources.md)（`function=greenhouse`）  
- 主设备：`grow_rack`（种植架），`slotCost=1`；高级 `grow_rack_dual` 占 2 槽、efficiency 更高  
- 需 1 名 `grower` 在岗才产出；无人记 0（[04 §4.2](04-population.md)）  
- 气候减产走 `greenhouseClimate`（冷侧），与日历「冬」脱钩；冷侧可开供暖把 0.50 抬到 0.95（0.30 燃料/节/日，[01 §8.1.1](01-time-season.md)）

### 3.4 其它主设备（快照）

| id | 设备 | 壳 | function | 岗位槽（job） |
|---|---|---|---|---|
| `workbench` | 工作台 | workshop | workshop | `crafter` ×2 |
| `workbench_adv` | 高级工作台 | workshop | workshop | 同上（占 2 槽） |
| `med_bay` | 医疗台 | medical | medical | `pharmacist` ×1（治疗+药品+药剂） |
| `med_bay_adv` | 高级医疗台 | medical | medical | 同上（占 2 槽） |
| `radar_array` | 雷达阵 | radar | radar | `radar_op` ×1 |
| `purifier_unit` | 净水机组 | water | water | `purifier` ×1 |
| `purifier_unit_adv` | 高级净水 | water | water | 同上（占 2 槽；efficiency 可至 150） |
| `grow_rack` | 种植架 | greenhouse | greenhouse | `grower` ×1 |
| `grow_rack_dual` | 双层种植架 | greenhouse | greenhouse | 同上（占 2 槽） |
| `engine` | 引擎 | power | — | `engineer` ×1/节（不可卸） |
| `bunk` | 床铺 | living | — | 床位（不占岗位） |
| `cargo_rack` | 货架 | cargo / living 辅 | — | 库存（living 上装则 +8 粮水上限，见 02） |

`guard` / `labor` 不绑设备槽；战斗名册见 [04 §4.6](04-population.md)。配置权威：[`data/equipment.json`](../data/equipment.json)（id 须与本表一致）。

## 4. 工坊动作

均由在岗 `crafter` 执行（改装类需停靠；无人则不可开工坊面板日动作）。

| 动作 | 规则要点 |
|---|---|
| 安装/卸载设备 | 槽位与白名单见 §3；卸载主设备则 `function=null` |
| 体积拼装 | 两节同 templateId、size=2 → 一节 size=4；**总容积不变，刹车不变**；设备合并不得超新槽位 |
| 体积拆分 | size≥3 → 按下表拆两节；装甲值平分（各 `⌊armor/2⌋`）后 <70 不再计装甲车；设备按槽位迁入，总 `slotCost` ≤ 两节新槽位之和，放不下的卸库存 |
| 功能重分配 | **仅同壳主设备变体互换**（下表白名单）；**禁止**改 `templateId`、禁止换出他壳功能；卸主设备 → `function=null` |
| 装甲焊接 | armor +10（上限 100）；speedBonus −2 |
| 动力改装 | **仅 isLocomotive** 且当前 `speedBonus < 20`；+5（上限 +20）；该节油耗 +0.5%/日。开局模板动力多为 **+20 已封顶** → 本动作灰显；主要服务发现的弱动力壳 |
| 精度校准 | efficiency +15 |
| 回收 | 按修复成本 70% 返还 |
| 造零件 / 精炼 | 日模式互斥二选一（XOR）；见 [02 §3.2/§5.1](02-resources.md) |
| 失护检修 | 见 §6.3；与车体维修一分列 |
| **遗弃车厢** | 见 **§4.1**；与「卸载设备 / 体积拆分」不同，整节脱离编组 |

### 4.1 遗弃车厢（脱钩 · 权威）

整节从 `train.carriages[]` 移除；**不入库存、不改 `templateId`、不回发现池**。与工坊「回收设备 70% 零件」相比：**返还更低、不可逆**，避免「先挂再扔」刷发现。

| 项 | 规则 |
|---|---|
| **时机** | `driveIntent=stop` 且（进站流程中 **或** 当日未再分配行驶小时）；**禁止**战斗插入、尸潮应对中、任意成员 `taskState` 为车外搜索/搬运未完成时 |
| **操作面** | 列车侧视 / 工坊面板「遗弃」；须先选具体 `carId` |
| **工位** | **不占** `crafter` 工位、**不计入**工坊日 XOR（与上表「安装/拆分」不同）；仍须 **停靠** |
| **动力红线** | 遗弃后 **至少保留 1 节 `templateId=power`**（`isLocomotive`） |
| **人口红线** | 该节绑定乘员（`carId` 指向此节）须先迁床或过道；遗弃后全车 `beds < onboard` → **禁止确认** |
| **岗位** | 该节在岗岗位（engineer / grower 等）须先召回或转岗 |
| **消耗** | `parts` ≥ `train.abandonPartsCost`（[`balance.json`](../data/balance.json)）；另扣 `fuel_cap × train.abandonFuelCostPct` 切割用油（计入当日 F04，不进工坊） |
| **返还** | `scrap` += `⌊repairCost(car) × train.abandonScrapRatio⌋`（`repairCost` 同挂车一口价：living/cargo **3**，其余 **5**）；**不**直接返 `parts`（低于工坊回收 70%） |
| **时间** | 占用 **0.5 游戏日** 切割（从当日 `driveHoursPerDayCap` 余量扣；不足则仅能「整日停靠」下执行） |
| **世界** | 脱钩节 **不**生成路段 `lootPiles`（防刷）；叙事上视为弃置路旁 |
| **与 08 软规则** | 油紧时 **R2 节流新挂** + **R6 甩节减负** 并列（属 R1「勿只挂动力」的多手段集合；R1 表内未逐条列 R6，见 **T11**） |

**埋点**：`carriage_abandon` + `templateId`、`carsAfter`、`fuelFill`（[09 §4](09-data-platform.md)）。

**零 A sim**：可实现简化 AI 在极油红时甩高耗节；**不**改变 Item6 主阈（pop/beds）。常量见 `balance.train.abandon*`（**玩法键已落盘；冻结乘子见 [10 §1.1](10-validation.md)，不在此阶段为对表改数**）。

**体积拆分尺寸（权威）**：

| 原 size | 拆成 |
|---|---|
| 3 | 1 + 2 |
| 4 | 2 + 2 |
| 5 | 2 + 3 |

拆后两节继承同一 `templateId`；`speedBonus`/`efficiency`/`trait` 复制到两节（动力资格仍只认 `templateId=power`）。禁止拆出第三种尺寸组合。

**同壳主设备白名单（功能重分配唯一可选对象）**：

| templateId | 可互换主设备（同列内） | 卸空后 function |
|---|---|---|
| `workshop` | `workbench` / `workbench_adv` | null |
| `medical` | `med_bay` / `med_bay_adv` | null |
| `radar` | `radar_array` | null |
| `water` | `purifier_unit` / `purifier_unit_adv` | null |
| `greenhouse` | `grow_rack` / `grow_rack_dual` | null |
| `living` | `bunk`（可拆腾槽给 `cargo_rack`；床≠主功能） | null（休息壳无 `function` 字段消费） |
| `cargo` | `cargo_rack` / `cargo_rack_wide` | null |
| `armor` | `armor_frame` | null |
| `power` | 引擎组件**不可卸**（卸=失去动力资格，禁止本动作） | — |

禁止把「功能重分配」理解成休息壳↔种植壳等跨功能变种（红线 #13）。

**工位互斥（权威）**：某 `crafter` 当日若已投入车体维修一 / 失护检修 / 改装动作（占用游戏小时），则**不计入**当日造零件/精炼在岗工位（[02 §3.2](02-resources.md)）。禁止同一人「修车 + 全日产零件」。

**功能重叠惩罚**：同 `function` 前 2 节不惩罚；从第 3 节起乘 `0.90^max(0, n−2)`。  
与软目标「≥2 种植车厢 + ≥2 净水」一致。

## 5. 发现与进站

车站**是否存在、规模、有池/无池**：由 [06 §0/§1.1](06-region-events.md) 在区段生成时写入；本表只定义各规模的发现池。

| 车站 size | 池 | 发现数量 |
|---|---|---|
| `small` 小型 | 休息、货舱、空壳 | 1–2 |
| `medium` 中型 | 工坊/医疗/雷达/**种植**/净水、空壳 | 1 |
| `large` 大型 | 动力/装甲/高级功能、空壳 | 1–2 |
| `none_pool` 无池 | — | **0**（可搜刮/事件，无车厢池） |

状态：完好 15% / 受损 60% / 残骸 25%。  
「进站无可获得车厢」（计入 `guaranteeFailStreak`）：无池站、空站检定（06）、池抽空、或**当站有车厢要约 offer 但修理价 > 当前 parts**。  

**保底（闭环）**：`guaranteeFailStreak ≥ guaranteeAfter`（基线 4）→ 下一有池站（`nonePool=false`）：

1. 强制生成 1 节可修**车厢要约** `offer`（跳过空站/无池）；状态至少为「受损」（非残骸）。**不是**事件选项。  
2. **可负担**：`repairCost = min(掷定价格, max(1, 进站时 parts 库存))`——保证进站当下修得起。  
3. 履约后 `guaranteeFailStreak = 0`。玩家拒修/暂不挂：该 `offer` **留本区域跨度 RegionRun**，可段内/跨段返程再挂；**跨度结束清除**（与下一轮三选一同步）。驶入下一段**不**清（仍可返程回该站）。拒修不重新累加失败（保底已兑现「必出可修」）。  
4. 教程强制站（§下）不计入 `guaranteeFailStreak`、不消耗保底。

**首小时钩子（强制，非概率）**：教程跨度第 0 段固定 1 座有池站（[06 §0.1](06-region-events.md)）；该站**跳过空站/无池掷骰**，首次进站（预期落在 dayTotal 3–5）必出 1 节**受损休息车厢**（`templateId=living`，修复 **1** 零件）——专教加床/过道压力。不计入保底计数。

权重与 `drawStation()`：配置 `stations.*`；区段生命周期锚点见 06 §0。

## 6. 驾驶 · 刹车 · 里程 · 车体

### 6.1 刹车 / 切轨（容积基准 8）

```
总容积 = Σ size
刹车耗时 = 速度 ÷ (15 ÷ (1 + 0.12 × max(0, 总容积 − 8)))
切轨耗时 = 0.3 + 0.08 × max(0, 总容积 − 8)
```

起始 3+2+3 = **8**，开局无惩罚。配置：`baseVolume=8`。

驾驶速度态：`STOPPED ↔ ACCEL/CRUISE/DECEL`（加减速目标 ±15 km/h）。  
**行驶意图**（与速度态正交，须存档）：

| 字段 | 取值 | 作用 |
|---|---|---|
| `driveIntent` | `forward` \| `reverse` \| `stop` | 决定 §6.2 前进/返程/停车分支与 F04 小时归属 |

`driveIntent=stop` 或瞬时速度 0 → 不推进里程。`reverse` 时速度态仍走 ACCEL/CRUISE/DECEL，但里程走返程式。  
速度上限见 §7 动力线。  
**车外召回**（与 [04 §5.7](04-population.md) 同一口径）：速度 **> 8 km/h** → 搜索/搬运人员强制召回；进行中搜索进度作废；**点位临时堆不清零**（可返程再搬，除非被掠夺者等夺走）。已装进列车的物资保留。
### 6.2 里程推进（行驶日额度 · 与 0.13 段/日对齐）

面板 0–80+ km/h = **战术瞬时速度**（刹车/碰撞/召回），**不是**「一天按此时速跑满 24h」。  
战略推进靠 **行驶日额度** `driveHoursPerDayCap`（[01 §2.2](01-time-season.md)）：每日只折合有限有效前进小时，用来锁区域节奏。

**量定义（唯一实现口径）**：

| 符号 | 定义 |
|---|---|
| `Δh` | 本 tick **意图小时** = `(本 tick 推进日数) × 24`（[01 §2.1](01-time-season.md)） |
| `driveHoursToday` | 当日已消耗的**有效前进小时**；存档；封顶 `driveHoursPerDayCap` |
| `reverseHoursToday` | 当日返程意图小时；存档；**不**占额度 |
| `travelBudgetExhausted` | `driveHoursToday ≥ driveHoursPerDayCap`（派生布尔；供 UI/油耗） |
| 重置 | `onDayStart` **步骤 0**（[02 §8](02-resources.md)）：先用昨日小时结 F04，**再**前进/返程小时归零 |

```
综合旅行速度(km/h) = 2.5 × (当前瞬时速度 / 30)   # 仅乘进有效前进/返程 Δh

# 前进：占行驶日额度
若 driveIntent=forward 且速度>0:
  若 travelBudgetExhausted:
    Δh_eff = 0                    # 当日不再加 progressKm
    # 油耗速度系数本 tick 强制按停车 0.3（02 §4）；UI 提示「今日推进额度已用尽」
  否则:
    Δh_eff = min(Δh, driveHoursPerDayCap − driveHoursToday)
    progressKm += 综合旅行速度 × Δh_eff
    driveHoursToday += Δh_eff
# 返程：不占额度；可跨段（见下）
若 driveIntent=reverse 且速度>0:
  remain = 综合旅行速度 × Δh
  循环直至 remain≤0 或无法再退：
    若 progressKm ≥ remain:
      progressKm -= remain; remain = 0
    否则:
      remain -= progressKm
      若 segmentIndex > 0:
        segmentIndex -= 1
        progressKm = segments[segmentIndex].lengthKm
      否则:
        progressKm = 0; remain = 0
        强制 STOPPED；禁止本 tick 继续返程
  reverseHoursToday += Δh
# stop 或速度 0：不加里程
```

| 项 | 口径 |
|---|---|
| `driveHoursPerDayCap` | **1.0** 游戏小时/日 = 行驶日额度（`balance.time.driveHoursPerDayCap`） |
| 额度用尽 | 前进里程停；**F04 速度系数按 0.3**（与「停靠」同档），即使面板仍显示速度；推荐玩家改 `driveIntent=stop` 或停车 |
| 权威节奏 | [01 §2](01-time-season.md)：**0.10–0.17 段/日**（中位 0.13） |
| 折算校验 | 瞬时 80 → 综合 ≈6.67 km/h × **1.0**h 额度 ≈ **6.7 km/日**；段长 50 → ≈ **0.13 段/日** |
| 返程越界 | 扣穿 0 且 `segmentIndex>0` → 上一段；第 0 段夹 0+STOPPED |
| 禁止 | 按面板时速×24h 推里程；额度用尽后仍按巡航/高速计油；返程在第 0 段空转耗油 |

其它：停车或速度 0 → 前进里程 0；**返程**可减 `progressKm` 并跨段回退下标、不增累计里程、**不**计入 `driveHoursToday`，但累加 `reverseHoursToday`（供 [02 §4](02-resources.md) 油耗）；区段前进结束见 06 §0。

### 6.3 车体（失败条件「车体=0」的唯一血条）

| 项 | 规则 |
|---|---|
| 起始 / 上限 | 100 / 100（全局一条，不设每节第二血条） |
| 碰撞伤害 | `基础 × (速度/40)² × (1 − trainDR)`；路障基础 12，尸群基础 8；`trainDR` 见 §6.4 |
| 触发 | 同轨、相对距离 < 45 m、速度 > 12 km/h |
| 撞击后 | 速度 ×0.55；目标速度锁 25，持续 **5/180 游戏日**（=1× 下约 5 真实秒；随倍速缩短墙上时间；**暂停冻结**，见 01 §2.1） |
| 低速遇尸群 | `0 < 速度 ≤ 12`：强制进入减速至 **0**，然后按停车遭遇走 [05](05-combat.md) **战斗层级** L1/L2（或事件）；**减速完成前**每 `1.8/180` 游戏日碾压 −4 车体；**已进入战前暂停后停止碾压**，禁止边战边扣 |
| 维修一 | 工坊：车体 +8/次，耗 2 零件，4 游戏小时，需 2 名 `crafter`（`repair` → 时长 ×0.85） |
| 失护检修 | 停靠 + 工坊：1 名 `crafter` 或该节 `engineer`，1 游戏小时，**0 零件** → 清除该节失护状态（[04 §4.7](04-population.md)） |
| 维修二 | 事件支援：偶发车体 +10–20，免费；**不**自动清失护 |
| 车体 < 30 | 速度上限 −30%；抛锚见下 |
| 车体 = 0 | 列车毁灭，失败结局（优先级 1） |

**抛锚（车体 < 30）**：

| 字段 | 规则 |
|---|---|
| `breakdownCounter` | 自上次抛锚起，**车体持续 <30** 的完整日结次数；存档 |
| 触发 | `onDayStart` **步骤 8b**（[02 §8](02-resources.md)）：若 `bodyHp < 30` 且 `breakdownCounter ≥ 3` → 强制 STOPPED **2 游戏小时**，然后 `breakdownCounter = 0` |
| 日累加 | 同一步：若 `bodyHp < 30` 且本日未因本条刚触发抛锚 → `breakdownCounter += 1`；若 `bodyHp ≥ 30` → **清零** |
| 禁止 | 另用日历「每 3 日」壁钟；禁止车体修好后仍保留旧计数 |

车体**不会**自然恢复。零件「永远不够」的主要消耗口之一。  
EA 后「车厢即战场」只做功能禁用，不另开血条。

### 6.4 碰撞与装甲 · 手算样例（权威校验）

**符号（与 §7 装甲线同一套；缩写总表见 [architecture §8.1](../architecture.md)）**：

```
装甲车数 armorCars（文内可写 N）= 满足 armor≥70 的车厢节数
装甲科技等级 armorTechLv（文内可写 L_arm；**禁止**写成战斗层级 L1/L2/L3 或异能 Lv）
列车碰撞减伤率 trainDR（文内可写 DR）= min(0.30×armorCars + 0.06×armorTechLv, 0.80)
  # 仅碰撞 / 碾压 → 扣车体；不进战斗 outE
装甲战力值 = 12×armorCars + 4×armorTechLv   # 仅进战斗式的 B（守卫合计侧）

碰撞伤害 = 基础 × (瞬时速度/40)² × (1 − trainDR)
  路障基础 = 12；高速撞尸群基础 = 8
触发：速度 > 12；速度 ≤12 走 §6.3 低速遇尸群，**不**用本式
```

#### A. 装甲减伤率 / 战力

| armorCars | armorTechLv | trainDR | 战力 | 备注 |
|---|---:|---:|---:|---|
| 0 | 0 | 0 | 0 | 开局无装甲 |
| 1 | 0 | 0.30 | 12 | 挂上首节装甲壳 |
| 2 | 0 | 0.60 | 24 | |
| 2 | 2 | 0.72 | 32 | `0.60+0.12` |
| 3 | 5 | **0.80** | 56 | `0.90+0.30` 触天花板 0.80 |
| 0 | 5 | 0.30 | 20 | 无装甲车时科技仍给 `0.06×5` 减伤与战力 |

#### B. 碰撞伤害（路障基础 12）

| 情境 | 速度 | trainDR | 计算 | 伤害 |
|---|---:|---:|---|---:|
| 开局无甲，中速 | 40 | 0 | `12×(40/40)²×1` | **12** |
| 开局无甲，满速 | 80 | 0 | `12×(80/40)²×1 = 12×4` | **48** |
| 1 甲、装甲科技 0，满速 | 80 | 0.30 | `12×4×0.70` | **33.6** |
| 2 甲、装甲科技 0，满速 | 80 | 0.60 | `12×4×0.40` | **19.2** |
| 2 甲、装甲科技 2，满速 | 80 | 0.72 | `12×4×0.28` | **13.44** |
| 3 甲、装甲科技 5，满速 | 80 | 0.80 | `12×4×0.20` | **9.6** |
| 无甲，刚过阈值 | 13 | 0 | `12×(13/40)²×1 ≈ 12×0.1056` | **≈1.27** |
| 速度 = 12 | 12 | — | **不触发**本式 → 低速遇尸群 | — |

#### C. 高速撞尸群（基础 8；对照路障）

| 情境 | 速度 | trainDR | 伤害 |
|---|---:|---:|---:|
| 无甲满速 | 80 | 0 | `8×4×1` = **32** |
| 2 甲、装甲科技 2，满速 | 80 | 0.72 | `8×4×0.28` = **8.96** |

#### D. 撞击后状态（例：撞击前 80）

```
速度 := 80 × 0.55 = 44
目标速度锁 25，持续 5/180 游戏日（暂停冻结；1× 下约 5 真实秒）
车体 := 车体 − 上表伤害（再 clamp 到 ≥0；到 0 → 失败优先 1）
```

满速无甲撞路障一次：车体 100→52；再来一次同条件 →4；第三次可能毁灭——说明开局满速硬撞不可持续，须减速或上甲。

**禁止**：用综合旅行速度（§6.2）代入碰撞式；碰撞只认**面板瞬时速度**。  
**禁止**：把 `gear.defense` 单兵减伤并进 `trainDR`（[05](05-combat.md) 分列）。  
**禁止**：战斗层级 L2/L3 对 `outE` 再乘 `(1−trainDR)`——战斗侧只吃「装甲战力值」进战力式 `B`（[05 §7](05-combat.md)）。

## 7. 四线科技

**成本权威**：[`data/upgrades.json`](../data/upgrades.json) `levels[]`（零件 / 药品 / 催化 / 燃料 / 图纸）。`balance.json` 的 `tech.*` 数组为 **sim 镜像**，须与 `upgrades.json` 逐级一致；客户端 UI 只读 `upgrades.json`。

资源成本：

| 等级 | 成本 | precision |
|---|---|---|
| Lv1 | 2 零件 + 1% 燃料 | ≥20 |
| Lv2 | 4 零件 + 1 药品 | ≥40 |
| Lv3 | 6 零件 + **催化药剂 1** | ≥60 |
| Lv4 | 8 零件 + **催化药剂 2**；须该线 `blueprints=true` | ≥80 |
| Lv5 | 10 零件 + **催化药剂 3**；须该线 `blueprints=true` | ≥100 |

Lv3+ **禁止**直接扣 `crystal`；须先由药剂师配制 `potion.catalyst`（[02 §5.4](02-resources.md)）。  
**图纸不消耗**：`blueprints` 为四线布尔资格，键名 `power` / `armor` / `radar` / `living`（生活线；与 `upgrades.json`、`templateId=living` 车厢同名，**不用** `life`）；升级只检查，不扣、不清（[02 §2.3](02-resources.md)）。

- **无跨日研发天数**。停靠且门槛满足 → 当场升级。  
- 第一辆工坊挂上时 `precision` 初值 **40**（立刻可升 Lv1–2；Lv3 需再养约 20 个造零件日，避免初值 60 使前三级门槛形同虚设）。  
- 造零件：`precision/300` 件/日；**造零件日** +1 precision；**精炼日** precision **不变**；**空转**（有工坊无有效 crafter 工位或未选日模式）−1/日；造零件与精炼同日互斥（[02 §3.2](02-resources.md)）。  
- `crafter` 出车搜索的当日：该人**不占**造零件/精炼工位（[04 §4.3](04-population.md)）。

**动力线**：

```
牵引效率 = max(0.40, 1 − 0.08×min(动力车数,3) − 0.08×科技等级)
```

| 3 动力车 | 牵引效率 | 说明 |
|---|---|---|
| Lv0 | 0.76 | 减免 24%，**未**触地板 |
| Lv5 | 0.40 | 此处才夹到地板 |

速度上限：`(60 + Σ(speedBonus 最高的最多 3 节动力车) + 5×等级) × speedClimate`（见 [01 §8](01-time-season.md)）。  
1 节模板动力车（+20）、Lv0 → 80 km/h。  
动力看护：每节动力车需 `engineer`；无看护则日 10% 失护故障，触发后速度上限 ×0.85，直至 **失护检修**（§6.3）成功或满 1 游戏日自动解除（[04 §4.7](04-population.md)）。车体维修一**不**清失护。结算：先算上式，再乘失护惩罚。

**油压应对（策划指引 · 零 A 沉淀）**：燃油压力须 **多手段并用**，禁止教程/提示只推「再挂一节动力」。并列五腿：

| 腿 | 作用 | 代价 / 注意 |
|---|---|---|
| 动力科技 | 单动力也可降牵引 | 与装甲/生活抢 precision·零件 |
| 停靠 / 额度尽 | 速度系数 0.3 省油 | 里程变慢 |
| 货厢 | 抬油容，服务秋储 | 占节数与维修零件 |
| 第 2–3 节动力 | 再降牵引 | 每节 +0.5%；占 `engineer` |
| 关供暖 | 省独立扣项 0.30/种植节 | 冷侧粮产回落 |

长编组油紧时：**软建议**暂缓装甲等 +2.0 高耗车（无硬节数上限；见 [08 §4 R2](08-presentation.md)）。

**装甲**：`trainDR` **只用于碰撞/碾压车体**；战斗用战力 `12×armorCars + 4×armorTechLv`。公式与手算见 **§6.4**。  

**雷达（须在岗）**：

```
staffedRadar = 有 radar_op 在岗的雷达车节数   # 空岗节不计；兼搜当日该节空岗
visionRaw    = 1 + staffedRadar + 雷达科技等级
effectiveVision = visionRaw × weather.visibilityMult
# 无 ClimateInfluence.visibility 通道；禁止再乘 Π influence
```

| effectiveVision | 效果 |
|---|---|
| <1 | 前方预警关闭；三选一无线索加成 |
| ≥1 | 前方预警开启（距离随 vision 线性，基线 1→短距） |
| ≥3 | 三选一**额外 +1** 模糊线索（[06 §1](06-region-events.md)；最多再 +1，不叠多条） |
| ≥5 | 本段资源点未搜类型多揭示 1 类图标 |

`night_rain` / `blizzard` / `fog` 的尸潮·搜索险内容权重 × `(1 − 0.08×雷达科技等级)`（地板 0.60）——雷达是**减险**，不是加尸。  
禁止「夜间尸群权重随雷达等级上升」。

**生活**：床位见 §3.2（预满时 `Σ(living 床位) + 2×等级`）；**科技床**优先摊入已有休息车空床槽（提高该节容量），摊不下才允许过道；库存 ×(1+0.10×等级)（晶核、药剂、装备、图纸除外）；**心情日恢复 +0.2/级**（[04 §9.1](04-population.md)）。

升级**不**触发对应资源点权重下调。
