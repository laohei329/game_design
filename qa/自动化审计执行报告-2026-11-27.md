## 1. 本轮修复的工具缺陷

这些是审计执行过程中暴露的**工具自身问题**，已修复并重跑：

1. **`client/scripts/debug/save_migration_probe.gd:55`**  
   `var infl_n := infl.size() if ...` 在 `infl` 为 `Variant` 时无法推断类型，导致 Godot 编译失败。改为显式 `var infl_n: int = int(infl.size()) if ...`。

2. **`client/scripts/debug/hc_config_probe.gd:35`**  
   直接引用自动加载名 `LocaleDb`，在 `--script` 无头模式下不存在，导致配置探针编译失败。改为在文件内预加载 `res://scripts/data/locale_db.gd`，调用其静态 `editor_translation_paths()`。

3. **`tools/probe_save_migration.py:23`**  
   清单校验把链尾 `to` 值期望写成 `2..12`，而实际十步的 `to` 是 `3..12`，导致假失败。改为期望 `3..12`。

4. **`tools/run_module_tests.py`**  
   - `_run_script()` / `_run_ps1()` 使用 UTF-8 + `errors="replace"`，并对 `stdout`/`stderr` 为 `None` 做保护，避免中文控制台输出导致 `UnicodeDecodeError` / `TypeError`。  
   - PowerShell 调用加入 `-ExecutionPolicy Bypass`，避免本机执行策略导致 `UnauthorizedAccess`。

5. **临时重复工具退场**  
   本轮重建的 `tools/run_zero_a_min.py` 已改成转发到官方 `tools/run_zero_a.py` 的弃用壳；`qa/ZERO_A_500_auto.json` 已标记为 `superseded`。现行权威只有官方 runner。

## 2. 仍然失败：阶段零 A 数值闸

官方命令：

```text
python tools/run_zero_a.py --runs 250 --strict
run_zero_a: runs=250/strat max_day=240 seed_base=100003
  [conservative] surv120=1% pop20=23% fuel_fail=56% peak_med=10
  [expansion]    surv120=2% pop20=20% fuel_fail=50% peak_med=8
  Item 1  [PASS] nan/neg cons=0.0% exp=0.0%
  Item 2  [FAIL] surv≥120d cons=1% exp=2% (need ≥40% each)
  Item 3  [PASS] death_peak cons=68% exp=62%; noncombat_kinds=4/4
  Item 4  [PASS] four-line Lv1-3≥5%
  Item 5  [PASS] drought≥8 con=1.6% exp=0.0%
  Item 6  [PASS] pop20Δ=-3% beds20 con=31% exp=32%
  Item 7  [SKIP] search≤3/点
  Item 8  [FAIL] exp pop20=20% peak_med=8 (need ≥30%, +5pp, med≥12)
  Item 9/10 [SKIP] 手算项
run_zero_a: FAIL
```

### 2.1 第 2 项还存在指标定义错误

`tools/run_zero_a.py:44` 把「存活≥120 日」写成：

```python
ok120 = sum(1 for s in states if s.day >= 120 and not s.failed)
```

这会排除**已经活过第 120 日、之后才失败**的局，不符合「存活到 120 日」的语义。用同一批官方种子（100003–100252）重算：

```text
official(day>=120 and not failed)  → conservative 2.8% / expansion 2.0%
reached120(day>=120 or not failed) → conservative 34.4% / expansion 34.0%
```

即：**runner 指标写错，但改成正确口径后仍低于 ≥40% 闸**。修复建议是把判定改为 `s.day >= 120 or not s.failed`，然后重跑；若不改指标，第 2 项的 1%/2% 不可作为真值。

### 2.2 第 8 项是真实未过

扩张策略 `pop≥20` 为 20%（闸 ≥30%，且需 ≥保守 +5pp；保守为 23%），`peak onboard` 中位数为 8（闸 ≥12）。第 6 项因 `beds20` 扩张 32% ≥ 保守 31% 而通过，但第 8 项没有替代口径。

按 `modules/10-validation.md` §1.1，解冻需写明原因、升级配置版本并重做 `@500`；本轮只登记，不建议直接改冻结数值。
